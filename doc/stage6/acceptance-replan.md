## 2. 为什么撤换

1. **把证明手段变成产品需求。** 第六阶段要求确定性 Watch、有界资源、隐私和可靠退出；不要求开发一个
   通用 ETW 文件取证产品。完整 FileObject/Key/IRP/Name 世代关联不是唯一可接受证明。
2. **同步模型不适合被测系统。** 每10秒暂停调度并等待多组 OS API，既改变产品运行，又让采集器尾延迟
   决定整轮成败。外部指标本来就不能宣称全部来自同一个原子瞬间。
3. **假定了 API 未承诺的能力。** Microsoft 未给 RmGetList 一秒完成保证；多数 Job completion 消息不保证
   投递，收到 PID 时进程可能已退出；ETW 跨 CPU 同时间戳顺序和丢失有明确限制。不能据此说任何实现都不可能
   成功，但不能把理想条件当正式测量的必然保证。
4. **流程强化了串行依赖。** 微小工具补丁反复经历冻结、独审、哈希、激活、UAC就绪、短测、原件审核；
   对总体可行性的判断太晚。用户已给工程自治授权，继续追问路线许可没有依据。
5. **事实源失去可维护性。** 进度文件混入完整历史，工具源码不入Git，旧角色和旧停止条件又与新授权并存。

API依据：[RmGetList](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmgetlist)、
[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、
[Job completion port](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_associate_completion_port)、
[ProcessTrace](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-processtrace)。

## 4. 隐私与实际可行性

同账户目录pin和app.setPath只能证明特定路径/时段的结构，不能证明启动前没有任何真实profile读取。
不能删掉ETW要求后直接宣布隔离通过。默认完整资源实测使用**无真实AIbrowse数据/凭据的独立普通测试身份
或干净Windows测试环境**；身份隔离还须验证原用户profile/凭据路径不可访问，不能只看目录为空。
已有环境是否满足要查实际事实，不能编造“已准备好”。

如果只有当前真实用户环境，先检查已有早期隔离证据；不足时一次性提出准备测试身份/环境所需的具体权限和
物理操作。也可用成熟观测工具完成有界合成profile专项，但要事先审查采集范围和敏感数据处理，不再开发
通用ETW解析器。权限或环境准备期间继续完成可离线完成的采样器、反例测试和报告器。

安全专项必须覆盖启动、延迟/拒绝认证、正常退出、路径换绑拒绝、普通build不可达资格入口、真实凭据零读取。
未完成该门只允许安全环境中的测量形成分项结论，H3b总门仍未通过；不得以分项结果接受用户风险。
