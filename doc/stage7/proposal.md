## 2. 产品承诺与工程选择

本阶段不增加大型Agent能力。保持既有工具数量/权限、浏览器与模型能力隔离、确定性Watch事实、
正文零落盘、凭据只写不读和三个独立SQLite库。修复失败不能降低既有资源、安全或数据阈值。

| 决策         | 本轮选择与边界                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 交付对象     | Windows x64桌面应用；其它架构/平台不因本设计获得兼容声明                                                                                                       |
| 工程打包路线 | electron-builder + NSIS，复用electron-vite构建链并隔离release输出；E1先做目录版资格，E5完成安装器。精确依赖版本在E1查官方/锁文件并验证，不套用网页示例的旧版本 |
| 安装权限     | 默认按当前用户安装；不添加系统服务、自启或默认浏览器接管。稳定应用标识与实际userData路径须先核对再冻结                                                         |
| 卸载数据     | 保留用户数据；安装器只卸载所拥有的程序文件。清空数据另需明确用户操作，不能用卸载静默擦库                                                                       |
| 升级         | 本阶段先完成手工覆盖升级和失败恢复；不实现自动更新，不让网页/模型提供更新地址                                                                                  |
| 签名与发布   | 首个交付候选为未签名内部开发版，明确系统提示与发行限制。设计保留签名接口；公开发布、证书/CI secret及外部权限需届时落实，本轮不代用户公开发布                   |
| 备份         | 用户主动导出本地业务数据，可能包含私密内容；明确排除Key、DPAPI密文、Cookie/Chromium Session、原始正文和日志。普通CSV/Markdown导出保持原有范围                  |
| 性能         | 先测量冻结基线，再修真实回归；沿用Watch已有数值与非暂停方法，不复建全机取证系统                                                                                |

这些是当前工程方案。若资格反例证明不可行，先按同一产品承诺修订详细设计，再换工具；不靠逐轮试错或放宽阈值取得PASS。
暂无必须现在提供的凭据、证书或物理环境；E5独立Windows环境、E6实际发布才可能需要用户操作。

electron-vite官方同时支持builder与Forge；本项目选择builder以直接复用已有out目录，避免Forge输出目录冲突，
并采用其NSIS能力。配置必须正向列出可交付文件，不能照抄宽泛排除清单。
依据：[electron-vite分发](https://electron-vite.org/guide/distribution)、
[NSIS参数](https://www.electron.build/v26/docs/nsis/)（2026-10-03核对）。

## 3. 需要完成的差量

- **E1**：发行环境入口、UI权限与资源协议、Provider端点/凭据信任、下载/导航/IPC，及最小可复现目录产物。
- **E2**：真实旧schema升级、Research预备份、跨库维护态备份恢复、Conversation字节/路径边界。
- **E3**：网页/主UI崩溃恢复、Agent/Research/Watch中断与可操作错误，不把“日志记错”当恢复完成。
- **E4**：有界结构日志、主动诊断导出与预览、性能基线和有数据支撑的修复。
- **E5**：安装、升级、卸载和独立干净Windows真实检查，packaged通知/路径/单实例验证。
- **E6**：CI/version/tag/包清单、秘密扫描、最终红队及新独立Stage Auditor；明确交付渠道与已知限制。

详细接口与验收见[detailed-design](detailed-design.md)、[threat-model](threat-model.md)和[tasks](tasks.md)。

## 4. 风险承接

| 原项/边界                | 分级与后续责任                                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| P2-3会话字节上限         | E2闭合；50会话/200消息限制继续保留，不静默截断旧内容。Research仍留独立库，不能重新塞入会话JSON            |
| P2-4默认worker           | E1固化单worker并验证普通npm test路径；此前显式单worker的PASS仍有效                                        |
| P3冒烟效率               | E4按耗时证据优化重复等待，保留有意义断言；不单独阻塞产品                                                  |
| O-1会话UUID路径          | E2备份导入改变信任边界前必须闭合路径反例                                                                  |
| 真实Provider/登录站点    | 条件性NOT RUN仍保留；有实际验证价值且配置可用时按既有安全授权执行，不把Fake冒充真实                       |
| packaged通知             | E5必须实际验证安装后的权限/路由与隐私，不沿用preview冒充                                                  |
| 电池                     | 用户2026-10-03取消强制实测，续航、放电功率与电池模式资源表现未验证；不安排拔电，不宣称PASS/N/A            |
| 当前账户/历史失败        | 当前账户非OS沙箱，证明限于已审应用路径；BBC/NASA/default/GPU/short002/ETW/RM的unknown及原件继续保留       |
| 发行环境入口与受控UI失陷 | E1的新安全面；环境变量不能开启release开发能力，sender校验不等于真人确认，具体能力与剩余限制见threat-model |
| 数据本地明文             | 备份不是加密保险库；明示包含的私人字段与接收方风险，不扩大模型/网页读取权限                               |
