# 自定义主题色（2026-10-13）

## 产品范围

用户提供 Chrome 配色面板截图，要求增加可自定义主题色。设置的“外观”页提供预设色卡、自定义选色与
六位 HEX 输入、当前选择标记及恢复默认。浅色、深色、跟随系统仍为独立的颜色模式；恢复默认仅重置颜色。
颜色立即作用于标签栏、工具栏、应用背景与强调色，Windows 标题栏按钮区域同步；普通网页不注入主题样式。
错误、警告、成功及标签组标识保留原有语义颜色。选择跨重启保存，既有外观模式和其它数据不迁移或清除。

## 实现与边界

`src/shared/theme-colors.ts` 是配色的唯一纯逻辑源，接受 `null`（默认）或严格 `#RRGGBB`，统一小写。
根据基色派生浅深两套有限 CSS token：背景、面板、文字、强调色以及标签栏/工具栏/活动标签；默认配色
保留当前外观。renderer 使用固定变量名的 `light-dark()` 色对，主进程使用同一算法得到当前标题栏配色。
默认浅色的次级文字由 `#647086` 微调为 `#5d697e`，修正其在悬停/选中背景上的低对比度；默认标题栏和主色保持。
不接受任意 CSS、URL、原生窗口属性或函数。任意自选基色均须派生可读色，而非直接充当文字颜色。

专用 `aibrowse.themeColor` localStorage 键保存主题色，原 `aibrowse.appearance` 模式键保持原义。
缺失或无效色值使用默认色，读取不覆盖损坏值；写入失败保留此前选择并显示未保存反馈。恢复默认只写色键。
不改 `app-preferences.json` 的托盘设置契约，不新增外部存储、网络或模型能力。

现有 `ui.setAppearance(appearance, themeColor?)` 同步外观：旧 `{appearance}` 与新
`{appearance,themeColor}` 两种严格闭合 payload，颜色缺失/null 表示默认；远程网页不拥有应用 bridge。
主进程仅保存窗口生命周期内的 mode/seed，系统主题变化只影响 system 模式且不丢失 seed；关闭移除监听。
不设置 `nativeTheme.themeSource`，不强制改变网站自身的颜色模式。启动继续沿用既有主窗口默认模式到
renderer 恢复偏好后同步的时序，本轮不宣称改变首帧恢复机制。

## 验证

配色算法覆盖预设、黑/白/灰及高饱和色，验证实际文字与常用背景组合对比度至少4.5，焦点和选中标记
至少3；装饰性边界与禁用态不混作文字。依据
[W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与
[非文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)，不将局部配色检查
称为应用完整无障碍认证。

聚焦验证颜色解析/CSS注入拒绝、旧模式键兼容、失败写入、模式与色独立、恢复默认、IPC额外字段、系统变化
及标题栏一致性。真实隔离 UI 验证浅深/系统、预设和自选、600px布局、重启保存及原生标题栏同步，保留旧
外观/分组/内置脚本/手动 IDM 门。完成受影响质量检查与独立持久化/IPC审核，再构建内部候选更新 output。
