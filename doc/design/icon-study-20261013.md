# AIbrowse 图标调研与设计

调研日期：2026-10-13。范围：12 款浏览器和 10 款 AI 检索、阅读与信息管理应用，共 22 款。
用于 AIbrowse 新图标的形态与小尺寸设计，不采用第三方图标素材。

## 方法与证据边界

本表以官方产品、品牌、新闻或官方账号页面建立来源，再与本轮图像检索返回的视觉描述交叉核对。
工具返回的是图片链接、描述及显示占位，未向研究者提供可检查的像素图像；内置浏览器连接初始化失败。
因此，本表不声称已目视检查官方像素图、截图或安装包图标，也不声称完成了第三方图标的 16px 实测。
形态栏记录来源所支持的图形描述；小尺寸栏是设计推断，须在 AIbrowse 自身候选上实际验证。
各品牌可能有操作系统变体；表格不把某张营销图当成所有平台当前唯一图标。
未下载第三方图片，未将研究图片放入产品资源或仓库。

## 对 AIbrowse 的候选建议

以下是本轮设计推断，不是第三方品牌的官方设计意见。

1. 继承深海军蓝与青绿，减少颜色和层次。优先用青绿单主体、海军蓝底板或负空间，而非 Edge 式蓝绿卷曲渐变。
2. 用一个连续、厚实的几何主体形成识别；内部最多一个主要负空间。可以探索抽象字母 A 与浏览入口／阅读视窗合一的形态。
3. 第二方向可以是圆角折页或成对页面归于一个轮廓，体现信息浏览；需避免普通书签、钱包或信封的既视感。
4. 不继续“放大镜加独立星星”的组合。孤立小星、细眼睛、刻度、线路和点阵均容易成为小尺寸噪点。
5. 先在 16、20、24、32px 和黑白背景上检验轮廓、孔洞与边缘，再决定大尺寸的微渐变。小尺寸可以作光学修正，不能靠大尺寸质感掩盖糊合。
6. 至少保留纯色／单色审视版本，以验证身份是否独立于渐变。候选阶段比较原始尺寸，不只比较放大的宣传图。

Google 的官方案例说明，图标必须在实际系统背景和小尺寸中检查，颜色微调也可能改变任务栏辨认效果。
AIbrowse 后续应验证自身候选，而不能把上述第三方经验等同于本产品通过验收。

## 选定设计与资产约定

选定“折页视窗 A”：粗实体 A 兼具应用首字母与入口意象，中央三角留白形成视窗，右侧折面与横梁表达信息页。
延续深海军蓝底与青绿主体；层次只服务于大尺寸，字形和留白负责小尺寸辨认。
这属于本应用原创设计方向，不表示任何参考品牌背书，也未进行商标注册检索。

- 第一候选为折叠 b＋方向角，因容易联想到现有搜索品牌而放弃。
- 第二候选改为整体 A；发现底板左上存在生成残影，第三次只清理底板与边缘。
- 使用内置 image_gen，共三次；未调用 CLI/API、未注入凭据。选定 PNG 原样保存为
  `resources/aibrowse-icon.png`，SHA256 `1421abd6914eb1afb380a3c4e272036f4108c60026017bc836ae050e29e77c01`。
- `tools/build/application-icon.ps1 -Replace` 只做保留 alpha 的缩放及 ICO 封装，输出
  `resources/aibrowse.ico`；`-Check` 只读重建比较。尺寸为 16、20、24、32、48、64、128、256。
  源位图规范化与输出帧均固定 96dpi，源复制明确使用像素单位；不继承宿主屏幕 DPI。
  ICO SHA256 为 `3385472596f1d14cb8345208d6d4837f4cf3fe9864aab3ab6e90871a1ab91ecb`。
  当前采用同一母版；逐档视觉检查后如已清晰，无需为规则本身另画小尺寸。未声称进行了逐像素光学校正。
- Windows 主程序 PE、ASAR 托盘资源、MSI 的 ARP/快捷方式及 NSIS 外层安装器沿用唯一 ICO 引用。
  PNG 母版仅为受控设计来源，不扩大发行资源白名单。普通 Electron 开发窗口仍沿用其默认图标；发行窗口使用 EXE 图标。
- 本轮保持已有功能、数据和安全边界，不新增界面品牌位置，也不改变应用生命周期。

实际八档 1:1 浅深底预览已检查：16px 中 A、三角留白和下方开口仍可辨，深底上依靠亮青主体辨识。
证据在 `log/icon-design-20261013/preview-02/`；预览直接使用 ICO 帧，不代替操作系统图标缓存或物理托盘截图。
首版转换默认 DPI 引起字节漂移的失败与修复见任务文档；两版解码像素完全相同，未为通过检查改图案。
发行构建先运行 `npm run verify:icon`，确认母版与派生资产一致。
