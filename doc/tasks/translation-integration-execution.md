## 2. 原框架保留是验收目标

优先验证两条路径：

1. 固定官方客户端包＋窄宿主兼容：保留原popup/options/content、浮球、侧栏和业务流程。
2. 必要的受控客户端适配版：保留可用原UI和处理模块，仅改平台、凭据、网络、数据和增量功能接点。

必须区分两者的实际复用范围、资产身份及修改。只保留类似布局但换成自有React界面/分段引擎，属于自研替代，
不能报“原框架保留完成”，也不能在兼容困难时自动采用。局部安全修复/容器适配不等于重写免费功能。

优先保留：原位双语/还原、正文识别与分段、动态页规则、样式、浮球/弹窗/侧栏/设置、快捷键、输入/悬停/划词，
已开放的服务配置、手工术语/高亮/导入导出、基础字幕采集/合句/预取/同步/绘制、可用标准PDF和文件工具入口。
这些是保留优先项，不是所有账号/地区/模式均已证明免费。原有合法账号/订阅入口不伪造状态；自有能力清楚标识来源。

每个T项及必要子项建立结果：`原版保留 / 宿主适配 / 高级替代 / 待权益核验 / 外围不新增`。
记录原版证据、实际账号/模式/版本、保留资产、拟改接口、缺口原因、验收和状态。不能把“未标Pro”当免费证明，
也不能把“代码/按钮存在”当服务已可用。复合项拆开，比如基础合句与会员增强、手工术语与自动提取。
凡提出独立实现，必须指出具体原免费能力无法满足之处；不能因为线上引擎不在ZIP里就重写全部文档应用。

## 4. 先完成兼容与边界验证，再接高级服务

### P0：接管、身份与差量表

读取必要设计/实际代码，保护未知修改；核验固定包和证据存在及摘要。缺文件则按固定来源恢复并验摘要，不换版本逃避失败。
形成80项保留/适配/替代矩阵与最小接口清单，记录原包/适配包及许可依据。常规本机使用与拟修改/随包分发分别处置，
未闭合的分发条件不能阻止不依赖它的合成探针，但不可先将原包或改包塞入Git/发行包。

### P1：43.8.4合成宿主探针与任务隔离

在全新临时profile、受控本地页面、外网拒绝条件下验证必要API；工具源码放 `tools/`，原件放gitignored `log/`。
初轮单场≤180秒、单实例；同一失败假设连续两轮无新证据即换路。不执行第三方脚本来代替先验证宿主能力。

原manifest是全站/all_frames/document_start注入；同Session内taskOwned不是平台隔离。先证明：

- 普通用户页、Research页、Watch页在同Session、相同URL并存时，只有精确合格用户文档可运行客户端。
- 排除内容注入还不够；后台Tab枚举/消息、webRequest、动态注入、iframe/about:blank、导航与关闭竞态都须受限。
- 不通过仅URL黑名单、内容脚本早退或独立登录插件区代替任务边界；共享登录语义保持。
- 普通页翻译节点不会被可信采集当原文Evidence；记录网站状态间接影响，不能宣称零间接影响。

若无法约束原包Session级观察，优先调整装载为受控适配版并说明相同界面/功能如何保留；不能放松任务页安全门。

### P2：原UI与免费基础流程闭环

资源使用路径明确后，在受控页面和确定性翻译替身上验证原客户端；替身只证明接口，不冒充真实翻译效果。
保留原浮球、popup、侧栏、设置及对应导航，完成双语→还原、选区/输入、SPA、取消、原设置重启保持。
活动Tab查询与命令必须对应AIbrowse精确用户Tab，不能把任意webContents视为活动网页。
只补必要的开页/菜单/侧栏容器、后台容器、下载/截图等类型化能力，不建立全Chrome API通用兼容层。

### P3：凭据、存储与网络哨兵

在任何真实Key或页面正文进入前，用非真实哨兵数据验证：

- Key只在主进程DPAPI存储和请求执行处消费；原options/popup/content只得hasKey和非敏感配置。
  原UI若依赖读回Key，局部改输入/状态组件，不牺牲凭据红线维持像素完全不变。
- 导入导出、同步、缓存、日志、网页、Worker均不得出现Key；原设置/术语交互保留，底层按安全要求适配。
- 原遥测、远端配置、后台请求、账号同步和正文缓存逐条资格；无默认新增正文持久化、云同步或远程可执行代码。
- 模型/网页不获得shell、任意JS、HTTP代理、IPC、文件、SQL；主进程固定脚本/类型化Adapter不变成通用能力。
- 自定义Provider配置由受信用户设置；服务目标、协议、重定向、大小、并发、费用、取消和远端清理有界。
- 停用/导航/关闭/退出后旧消息、任务、结果不可继续作用；外部已受理调用不伪称已撤销费用。

原PDF桥接的通配postMessage不能照搬；精确校验origin/frame/任务token及文档世代。新能力经BrowserController/窄宿主服务，
不把应用preload塞入远程页，不扩展现有AI工具数，不改Research/Watch的既有产品承诺。

### P4：真实免费能力资格与回归基线

选择明确服务/账号/语种/模式，以小而有真值的样本测原免费路径；事前记录用途、请求/费用预算、数据政策和停止条件。
免费公平使用/429/额度均如实报告；配置Key不等于全部高级能力免费。真实Provider长期授权按现有规则使用，
凭据缺失写“凭据不可用”，不写成用户未授权；涉及新增计费/数据政策的选择按实际缺口集中确定。
得到哪些原能力已经满足、哪些仅宿主适配、哪些确实缺失的证据后，才展开相应高级替代。保留失败和基线输出。

## 5. 集成验收、失败换路与交付

- 同一固定原版在受控条件的输出/交互作为免费回归基线；验证保留资产、适配差量、UI操作与实际行为，不能只看截图相似。
- 保留项至少覆盖设置/浮球/侧栏、网页还原、动态DOM、输入IME、字幕播放/暂停/seek/倍速/全屏/切视频、图片恢复、
  标准文档入口。逐项处理不支持模式；高级服务失败不能破坏免费功能。
- 关键反例：同URL任务页隔离、文档/媒体过期、错误frame、恶意消息/输出、Key/导出/日志泄漏、配置损坏/并发、
  超额/429/断线/取消、远端清理未知、畸形字幕/归档/文档、缺段/漏页/公式改写。
- 质量先于速度。固定有人工真值的代表集后测原文准确度、漏句/幻觉、专名/数字、译文与术语；不能拿上游不可比WER排榜。
  再做同视频/分辨率/硬解条件的观看基线与翻译对照，测掉帧、停顿、积压、CPU/RAM/包体；此前未测观看保持NOT RUN。
  数值门、样本、预算、oracle在执行前冻结；产品容忍度不明时集中裁决，不降低阈值迁就失败。
- 纯工程适配可自主调整并同步设计；若需要整套重写、独立登录区、扩大权限、改变留存/外发或接受有损成品，
  先给具体约束、可行替代和影响，请用户裁决。无新证据不超过两轮重复同一失败假设，不无界补兼容API。
- 按风险运行聚焦typecheck/lint/test/build和真实Electron冒烟；关键安全/持久化/并发与最终集成需新独立上下文审核。
  不用替身、服务端成功状态、菜单存在或静态资料代替真实体验。保留失败与NOT RUN，不因部分完成关闭全部功能。
- 完成报告给出80项最终映射、原资产身份/适配diff、实际API与额度、准确度/性能/界面证据、未完成项和风险。
  未通过的高级能力明确未交付，不能用“基础API可用”冒充全部高级目标。
- 必要审核PASS后同步正式设计/任务/progress、提交并正常双远程推送；遵守GitHub代理规则，不强推、不夹带其他工作。
  仅在产品及包的适用验收通过后更新output，按当前打包/手动升级规则交付，不发布公共Release。
