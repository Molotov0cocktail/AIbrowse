# PROJECT_RULES.md — 通用工程开发规则

> 供项目裁剪的工程基线。用户当前指令和项目 `AGENTS.md` 优先；本文件不额外设立权限或审批门。
> 产品需求、工程设计、当前进度和机器证据各有职责，避免建立重复事实源。

## 1. 目标与授权

- 把用户已授权的目标持续完成到可验证、可审查、可交付状态。内部任务划分、提交或聊天结束不构成停工理由。
- 保持功能、体验、兼容性、安全、隐私、数据语义及实质性能/可靠性承诺。实现、架构、依赖和验证手段可由
  工程 Agent 选择或替换；失效方案先说明根因并修订正式契约，不为迁就失败降低验收阈值。
- 产品取舍、接受影响用户的未解决风险、凭据/外部权限、物理操作或未授权不可逆动作需要用户输入。
  多个内部工程方案不自动构成用户裁决事项；可继续不依赖待裁决项的工作。
- 角色用于明确规划、实现、审核和收尾职责，不绑定特定模型或外部工具。模型与开发协作按项目授权调度。

## 2. 接管与文档职责

1. 先看 Git 分支/状态/近期相关提交，记录精确 baseline，保留已有修改。远程与授权已知时不重复询问；网络
   操作遵守项目代理和权限规则。
2. 阅读当前进度入口、任务相关需求/设计/安全章节及实际代码/测试。按风险追溯依赖与历史，不要求每次全文
   重读全部阶段文档、审核所有历史提交或重跑未受影响矩阵。
3. 对“应该是什么”，依据需求与正式契约；对“现在是什么”，依据 Git、代码和机器输出。报告与历史 PASS
   只提供线索和证据索引，不能代替适用性判断。
4. 使用现有 proposal/设计/任务文档记录稳定决策，`progress.md` 只保留当前状态、证据索引和下一动作，执行
   历史留 Git 与受控原件。未经明确需要，不新增 handoff、Agent 日志或第二套长期状态文件。
5. 当前实施合同至少说明目标、非目标、baseline、产品不变量、工程选择、范围、验证、完成条件及停止/换路
   条件。充分的现有文档直接引用，不为形式复制设计或制造重复审批材料。

## 3. 实现、验证与审核

- 任务按完整可验证目标组织，可覆盖多个模块，可合并简单变更与文档收尾。对范围变化说明原因并协调写者；
  不机械限制一次一个文件，也不在每个小步或提交后停止已授权工作。
- 行为缺陷先建立能区分旧实现与正确行为的红态测试；安全、持久化和并发边界有反例。可逆低影响文档或
  配置修改采用直接检查，不编写重复实现或仅匹配措辞的测试。
- 工程契约错误先 REPLAN，再同步 oracle 和实现；不得删除有意义的断言、隐藏失败、跳过真实门或放宽数值
  阈值让现有实现过关。替换验证手段时说明如何覆盖原产品承诺。
- 从受影响的聚焦测试开始，在集成点完成必要全量和运行验证。通过后只因新改动、失败或未解决风险继续
  扩测；未受影响、版本与来源明确的证据可按范围复用。
- 每轮不确定诊断预设目的、预算、最小有效证据及停止/换路条件。相同路线连续两轮无新增证据时重定方案，
  不无界重试、不挑成功轮覆盖失败。历史根因不可恢复时保留 unknown，不能要求每次新证据恢复过去事实。
- 普通变更由主协调者复核即可。关键安全/隐私、迁移/持久化、并发、大规模架构变化和用户明确要求时采用
  新独立 Reviewer；阶段最终验收始终采用新的独立 Stage Auditor。独立审核按风险边界组织，不重复审核每个
  未改变的增量。
- Reviewer 独立核验候选与证据，输出 PASS / REPAIR / REPLAN / BLOCKED；实现者自述不构成 PASS。
  修复后复验受影响范围；阶段是否可关闭由当前 Exit Gate 的完整证据判断。

## 4. 工程红线

1. **能力隔离**：纯逻辑与 IO/平台能力保持清晰边界，不扩大不可信输入可调用的能力。
2. **安全失败**：敌手和越界输入按明确接口返回受控错误/空结果，不回显敏感内容或原始敌手正文。
3. **类型与依赖**：不以关闭严格检查、宽泛豁免、删除锁文件或强制安装绕过根因；版本与构建可复现。
4. **用户工作**：不覆盖未知修改，不未经授权执行破坏性动作，不夹带未授权产品需求。
5. **敏感信息**：凭据、真实用户数据、机器专属配置、原始运行日志/trace 与构建产物不入库；私有参数从
   仓库外受控输入，命令行/日志/报告不暴露秘密。
6. **工具源码**：通用采集器、判定器、回放器、合成夹具、测试与构建脚本是工程源码，放入项目受控 `tools/`
   或既有正式工具目录并纳入 Git。先剥离私有配置，不能把可复现工具永远藏在 gitignored 日志目录。
7. **生命周期**：资源按真实所有权幂等释放；观察器与产品分离，不能吞掉产品错误或用强杀冒充正常退出。
8. **证据保留**：只清理已确认无证据价值且属于本任务的临时产物。失败原件、请求/claim 账本与必要关联
   记录保留，不把历史失败当垃圾删除，也不将日志字符串当作行为证明。
9. **日志适量**：日志记录排障必需的状态、分类、版本和耗时，使用项目受控目录与脱敏/预算策略；不因追求
   “详尽”而记录正文、用户数据或无限增长。
10. **语言一致**：界面、错误、文档和提交按项目语言，代码注释按项目约定。

## 5. 风险相称的验证矩阵

| 变更             | 当前增量检查                                 | 集成/交付要求                                           |
| ---------------- | -------------------------------------------- | ------------------------------------------------------- |
| 纯文档/流程      | 相关一致性、变更文件格式、diff/敏感信息/状态 | 新事实声明核对实际来源；不跑无关全量测试或构建          |
| 逻辑/类型        | 甄别性聚焦测试、受影响类型/lint/格式         | 集成点按影响补回归；公共边界或依赖变化补 build          |
| UI/平台/进程     | 上述适用检查与构建                           | 受影响真实运行/冒烟，跨模块或发布候选完成必要全量       |
| 安全/持久化/并发 | 敌手、恢复、生命周期和相关集成检查           | 新独立 Reviewer；风险覆盖完整，必要全量与真实条件       |
| 验收工具         | 判定反例、原件回放、构建与短时可行性         | 新方案先证明可观测性与开销，再执行正式长测              |
| 阶段最终验收     | 当前候选要求的全量检查及构建                 | 新独立阶段审核、必要全冒烟/真实条件，逐项确认 Exit Gate |

实际命令、退出码、范围、复用证据与 NOT RUN 原因必须可查。不能用未执行的验证或不适用的旧 PASS 填补缺口。

## 6. Git 与交付

- 保留实现前 baseline，按逻辑创建候选及修复提交。所需审核 PASS 前不 push 为远程完成状态。
- PASS 后由主协调者或获委派 Closer 更新当前进度/必要正式文档、终检并提交推送；普通文档与收尾可合并。
- 不强推、不改公开历史、不用 amend 隐藏失败修复链。远程失败如实报告，保留可恢复的本地状态。
- 提交前检查 diff、敏感信息、用户修改和残留；只入库源码、测试、设计、构建与受控工具，不入库原始证据。
- 交付物相关修改必须重建并验证实际产物包含改动；发布操作须已有授权，发布后核对可获取的实际产物。
- 阶段结束完成独立验收后，只继续用户已授权的下一范围，不由模板自行扩大或缩小工作授权。

## 7. 协作与项目化

- 独立调查、互不重叠实现与风险审核可以委派；跨模块协调、根因结论和需求判断仍由主协调者亲自核对。
- 同一文件不并行写。受委派 Agent 只处理约定范围，发现依赖先协调；不擅自提交推送或改当前进度。
- 简单小改由当前 Agent 直接完成，避免交接大于工作本身。必须独立的风险审核不由实现者自审替代。
- 项目 `AGENTS.md` 保存稳定架构、红线、模型调度、命令与风险矩阵；当前 HEAD、计数与执行历史不复制进去。
- 新项目只补缺失且影响执行的信息；已有远程、语言、权限或授权不重复确认。文档模板按实际目标裁剪。
