# prompt-templates.md — 文档与协作模板（AIbrowse）

> 按任务模式选取所需模板，已有文档充分时只补差量。模板不增加审批门、不复制当前 HEAD/结果/凭据。
> 模型按 AGENTS.md 调度：主协调/规划/常规复核 `gpt-6-astra/high`；复杂诊断、安全、并发、阶段审核
> `gpt-6-astra/xhigh`；常规实现/测试 `gpt-5.6-sol/medium`，复杂实现可用 high 或 Astra。
> 用实际调度参数设置，未回显 actual 则记不可验证。

## 1. Proposal 模板

```markdown
# <功能/阶段> Proposal

- 目标与非目标：具体用户行为和本次授权边界。
- 用户场景、输入输出与失败体验。
- 产品承诺：功能、兼容性、数据语义、安全隐私、资源与可靠性。
- 约束分类：产品硬要求、可撤换工程选择、外部条件；分别引用来源。
- 外部依赖：已知能力、尚待验证假设与替代方案。
- 验收标准：每项承诺对应最小充分证据和客观 oracle。
- 待裁决产品项：影响与选项；内部工程选择由 Agent 给出理由后确定。
```

## 2. High-Level Design 模板

```markdown
# <系统/阶段> 高层设计

- 架构与数据流：模块/进程职责、能力边界和依赖。
- 关键工程选择：选择、理由、反证和可替换条件。
- 安全与存储：权限、敏感数据、生命周期、恢复与清理。
- 证据架构：确定性行为、真实集成、资源、环境条件分别如何验证。
- 风险与可行性：平台 API 能保证什么、不能保证什么；先验证哪些假设。
- 产品承诺保持表：旧承诺 → 新设计 → 验收方法，不能用方案更换隐含削减承诺。
```

## 3. Detailed Design 模板

```markdown
# <模块/系统> 详细设计

- 文件/模块职责与接口前后条件；实现后按实际代码核对。
- 不变量、状态、错误分类、并发、生命周期和数据语义。
- 非平凡算法、平台能力及诚实限制。
- 验收：承诺 → oracle → 采集来源 → 反例 → 通过/失败/证据不足分类。
- 可行性检查：最小负载、开销、预算、停止与换路条件。
- 验证范围：聚焦、集成、正式长时/真实条件、阶段最终门，说明可复用证据。
- 变更影响：替换或删除哪些旧工程合同，哪些产品承诺和数值保持。
```

## 4. 任务文件模板

```markdown
# <任务编号> <任务名>

- 目标、非目标与当前授权。
- baseline、相关设计/安全章节、当前已验证事实。
- 预期模块/文件及写者边界；范围变化如何协调。
- 实施顺序：按完整可验证目标，可合并相关模块与文档收尾。
- 不变量与工程选择；选择失效时的 REPLAN 条件。
- 验证：红态/反例、聚焦回归、集成点和正式验收。
- 完成条件：所需验证、风险相称审核、文档/提交/推送边界。
- 预算与停止/换路条件；外部依赖及可独立推进事项。
```

## 5. progress.md 模板

```markdown
# progress.md — 当前状态与短期记忆

> 状态与证据索引保持精炼；执行历史留 Git 和受控原件，不复制长篇日志。

## 当前入口

- 当前授权、阶段、任务、baseline/候选与已有工作区修改。
- 已核验状态与尚未通过的门；不得把历史或局部 PASS 扩大到整体。
- 下一动作及对应任务章节，外部条件与停止边界。

## 任务与风险

| 任务/风险 | 状态 | 当前事实与证据索引 | 下一动作 |
| --------- | ---- | ------------------ | -------- |

## 当前证据

- 命令/范围/退出码、构建身份、独立审核与原件索引。
- 复用证据的版本和适用范围；NOT RUN/unknown/失败及其影响。
- 累计请求/claim 账本索引，历史失败不可重置。
```

## 6. 验证与收尾模板

> 按 AGENTS.md 风险矩阵选择实际需要的检查；不默认给每次改动套全部门。

```markdown
- 变更风险及受影响范围。
- 已执行聚焦/集成/格式/diff/类型/lint/构建/冒烟的命令、结果。
- 必需全量、正式长时或真实条件的结果；未执行项及理由。
- 复用证据及适用范围；失败原件保留位置。
- diff、敏感信息、用户修改与残留检查。
- 所需 Reviewer 结论与覆盖候选。
- progress/正式文档同步、提交及授权推送状态。
- 剩余风险和下一项已授权工作；外部阻塞仅阻止依赖它的动作。
```

## 7. Planner / Execution Contract 模板

```markdown
你是 Planner。按 AGENTS.md 接管当前任务，核对相关章节、Git/代码和机器证据，不要求重读全历史。
纯设计任务只改设计；已有实现授权时形成合同后继续推进，不重复请求工程许可。

TASK / BASELINE

- 完整目标、精确 SHA、分支和已有工作区修改。

GOAL / NON-GOALS

- 可验证结果与用户授权边界。

AUTHORITATIVE SOURCES / CURRENT VERIFIED STATE

- 相关需求/设计/安全/任务章节；独立确认的事实、推断与证据缺口。

FIXED DECISIONS / INVARIANTS / RED LINES

- 保持的产品承诺、安全/隐私/数据与数值阈值。
- 当前工程选择、理由及何时可以自主替换；不把内部实现永久冻结。

EXPECTED SCOPE / IMPLEMENTATION PLAN

- 涉及模块、写者边界、依赖与集成点；必要重构和范围调整由主协调者说明并同步契约。

TEST PLAN / ACCEPTANCE

- 甄别性红态/反例、聚焦验证、必要集成/全量/真实条件、证据复用与完成条件。
- 可观测性假设、最小可行性检查及产品/采集器/环境失败分类。

STOP OR REPLAN CONDITIONS

- 预算、同路线无新增证据、工程假设失效时换路；不把架构变化自动升级为用户审批。
- 产品取舍、接受用户风险、凭据/权限、物理或未授权不可逆动作需要用户输入。

FINAL EVIDENCE

- 候选 diff/提交、实际命令与结果、原件索引、审核范围、剩余风险和工作区状态。
```

## 8. Executor 模板

```markdown
你是 Executor。核对当前合同、baseline 与已知候选差量，保护用户工作，完成已授权实现与验证。

- 行为缺陷先建立可甄别红态，安全/持久化/并发有反例；普通文档不为流程凑测试。
- 按模块目标实施，说明必要范围变化；受委派时协调写者，不修改他人负责文件。
- 工程假设失效时由主协调者 REPLAN 并同步设计；不得降低产品承诺或数值门迁就失败。
- 运行风险相称验证，保留全部失败。无新证据不连续重复同一路线。
- 审阅候选和工作区 diff，保留失败原件，仅清理无证据价值的自有临时产物。
- 可创建逻辑候选提交；所需审核 PASS 前不 push。受委派任务完成后向主协调者报告，
  主协调者持续推进后续已授权工作，不因内部小步完成要求用户确认。

返回 FINAL EVIDENCE：修改、候选身份、命令与结果、失败/限制、原件索引及下一动作。
```

## 9. Reviewer 模板

> 普通变更可由主协调者复核；关键安全/隐私、迁移/持久化、并发、大规模架构变化和用户要求时用新独立上下文。

```markdown
你是 Reviewer。实现者报告是线索，独立核对候选和证据。

1. 确认 baseline/候选/工作区，审查本轮完整差量与受影响模块，不重审无关历史。
2. 核对产品承诺、正式契约、不变量、范围与 Acceptance；工程方案可修订但必须保留验收实质。
3. 读关键代码与甄别性测试，按风险独立复跑必要检查；旧证据仅在明确适用范围内复用。
4. 检查文档、敏感信息、原始证据保留、残留与未解释失败。
5. 输出 PASS / REPAIR / REPLAN / BLOCKED，说明候选、证据、文件行号、实际验证与下一动作。

REPAIR 给出缺陷 oracle 和关闭条件；REPLAN 指出失效假设及需重定的工程方案或待裁决产品项。
所需审核 PASS 前不 push；后继变更只重审受影响范围，不把一次局部 PASS 当阶段通过。
```

## 10. Repair 模板

```markdown
你是 Repair Worker。先核对 Reviewer 发现与当前候选，再处理同一根因的完整影响面。

- REPAIR BASELINE：已审核候选及未提交修改。
- FINDING：具体缺陷、影响、已证根因与 unknown。
- SCOPE：相关模块、写者边界、必要设计修订。
- REQUIRED TEST：甄别性红态或反例，覆盖旧故障与正确行为。
- CONSTRAINTS：产品、安全、隐私、数据语义和资源阈值保持。
- ACCEPTANCE：关闭条件、受影响回归与必要独立重审。
- REPLAN CONDITIONS：根因假设失效或连续无新增证据时改变工程路线，不无界追加补丁。

完成聚焦/必要集成、diff 自审并返回候选与证据；审核前不 push，不把返回主协调者等同请求用户许可。
```

## 11. Stage Auditor 模板

> 必须使用新的独立 `gpt-6-astra/xhigh` 上下文。

```markdown
你是 Stage Auditor。在当前候选独立核验，不采信实现者自述或过期 PASS。

确认 Git/工作区、当前 Stage 验收、安全契约与依赖。核对关键实现，执行阶段要求的全量
测试、类型/lint/格式/构建、dev+production 冒烟、跨进程、红线/隐私与正式真实条件。
未受影响证据可核对版本和范围后复用；必要最终回归和独立判断不能省略。

逐项给出产品验收/Exit Gate 证据、结构性证明/真实观察/诚实限制、NOT RUN/unknown/失败、
文档一致性及未裁决风险。结论只能 GO/PASS 或 HOLD/PENDING。

发现缺陷按影响给出 REPAIR/REPLAN，修复后独立复验受影响范围；不要求重复无关检查。
PASS 后由 Closer 收尾，再按用户当前授权继续下一阶段入口/设计或停止，不由模板自设等待门。
```

## 12. Bug Triage 模板

```markdown
你是 Bug Triage Planner。确认版本、运行形态与症状，读受控原件并定位首个错误状态。
区分产品缺陷、契约/夹具、采集器和环境条件；列出已证事实、推断与 unknown。
检查旧测试为何未发现问题，给出最小甄别 oracle、影响面和下一条有预算/停止条件的路线。
历史不能恢复时不虚构根因；用当前充分证据处理当前阻塞，保留旧失败。
纯诊断授权不改产品；已授权修复则在合同清楚后继续实施。
```

## 13. Feature Change / REPLAN 模板

```markdown
你是工程 Planner。先把现有约束分成产品承诺、工程决定、验证手段、环境条件。
核对用户目标、数据/迁移、安全隐私、兼容性和验收；对已证失效方案给出替代架构和理由。
直接重写冲突的正式条款、任务与入口，避免仅追加“本条覆盖旧条”的长期叠层。
给出旧承诺到新证据的映射、最小可行性检查、实施顺序与明确停止/换路条件。
工程选择自主决定；只有产品取舍或接受用户风险等必要事项集中请求裁决。
纯设计轮完成文档与审查即停，不夹带产品实现；后续按授权范围推进。
```

## 14. Closer 模板

```markdown
你是 Closer。核对所需 Reviewer PASS 对应的候选，处理已授权收尾。

1. 更新 progress 当前事实、证据索引和下一动作；稳定设计/规则变化写入对应正式文档。
2. 检查 diff/status、相关格式、敏感信息及残留；保留失败原件与账本。
3. 完成逻辑收尾提交，不夹带产品行为变化，不改公开历史。
4. 按项目代理与用户授权正常推 Gitee/GitHub；失败如实报告并保留可恢复状态。
5. 报告 HEAD、远程/工作区、验证、限制与下一项已授权工作。

候选变化使 PASS 不再适用时仅重审受影响范围；不重复索取已有工程授权。
```
